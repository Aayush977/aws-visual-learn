## Where the marks actually go

Watch someone revise for this exam and you will see them making lists of services. Sixty
names, one line each, read until the lines blur.

Then watch them sit a practice test. They rarely meet a service they have never heard of.
What happens instead is that a question describes a situation, **two of the four answers are
both plausible**, and thirty seconds evaporate while they try to remember which one was for
which. They pick the wrong one, or the right one for the wrong reason, and either way they
have learned nothing they can reuse on the next question.

The exam is built this way on purpose. A question with three obviously wrong answers tests
nothing. Almost every real item is a **discrimination test between two services that overlap**,
and the discriminating detail is usually one clause in the middle of the paragraph.

So this page is not another list. It is the twelve pairs that do the damage, each one laid out
the same way: what each service actually is, when you reach for it, and — the part worth more
than everything else — **the exact wording in a question that points at it**.

<Callout type="exam" title="How to use this page">
Read it once now. Then come back to it after every practice test you take, and only look at
the pairs you actually got wrong. Ten minutes here, spent on the two pairs you keep confusing,
is worth an hour of re-reading lessons you already know.
</Callout>

## 2 · Storage

<Confusable
  title="EBS vs EFS vs S3"

      when: [
        'It is the <strong>boot volume</strong>, or a database\'s data files',
        'You need consistent low-latency block storage with specific IOPS',
        'Exactly <strong>one machine</strong> needs it',
      ],
      giveaway: ['"block storage"', '"boot volume"', '"IOPS"', '"attached to the instance"'],
    },
    {
      name: 'Amazon EFS',

      when: [
        '<strong>Several instances</strong> must read and write the same files simultaneously',
        'The application expects a real filesystem path and cannot be changed',
        'Content for a fleet of web servers, or a shared home directory',
      ],
      giveaway: ['"shared file system"', '"multiple instances"', '"concurrently"', '"NFS"'],
    },
    {
      name: 'Amazon S3',
      tagline: 'Object storage over HTTPS. Nothing mounts it; anything can reach it, from anywhere.',
      when: [
        'Uploads, backups, logs, static website files, a data lake',
        'You want <strong>eleven nines of durability</strong> and effectively unlimited capacity',
        'The thing reading it is not necessarily an EC2 instance at all',
      ],
      giveaway: ['"objects"', '"static content"', '"backup"', '"unlimited"', '"from anywhere"'],
    },
  ]}
  rule="Ask two questions, in this order: <strong>how many machines need it at once</strong>, and <strong>does it have to look like a filesystem?</strong> One machine → EBS. Many → EFS. Neither → S3."
/>

<Callout type="gotcha">
For a <strong>Windows</strong> file share — SMB, Active Directory integration — the answer is
<strong>FSx for Windows File Server</strong>, not EFS. EFS is NFS and Linux. This substitution
appears often enough to be worth its own line in your memory.
</Callout>

## 5 · Database resilience

<Confusable

        'Users on another continent need low latency writes',
      ],
      giveaway: ['"disaster recovery"', '"entire Region"', '"RTO"', '"RPO"'],
    },
  ]}

## Now test the ones that catch people

Reading a comparison and recognising it under pressure are different skills. These three are
where the marks are actually lost.

<Quiz
  question="A company needs to block traffic from a specific range of IP addresses that has been attacking their web application. The block must apply to every instance in a subnet. What should they use?"
  choose={1}
  options={[
    {
      text: 'A network ACL rule denying the IP range',
      correct: true,
      why: 'Network ACLs operate at the subnet boundary and are the only one of the two that supports explicit deny rules. Blocking a specific source is therefore always a NACL answer.',
    },
    {
      text: 'A security group rule denying the IP range',
      why: 'Security groups have no deny rules at all — they can only allow. There is no way to express "block this address" in a security group, which is exactly what this question is testing.',
    },
    {
      text: 'A route table entry discarding traffic from the IP range',
      why: 'Route tables decide where traffic goes based on destination, not source, and they are not a filtering mechanism.',
    },
    {
      text: 'An IAM policy denying the IP range',
      why: 'IAM controls who can call AWS APIs. It has nothing to do with network traffic reaching an application running on an instance.',
    },
  ]}
  explain="The reliable shortcut: <strong>a security group can only say yes.</strong> Any question containing the word <em>block</em>, <em>deny</em> or <em>prevent</em> at the network level is pointing at a NACL."

One last thing about how to use this, because it changes how much it is worth.

Do not read this page again from the top. After your next practice test, open it and look
only at the pairs you got wrong — and read the **giveaway phrases** rather than the
