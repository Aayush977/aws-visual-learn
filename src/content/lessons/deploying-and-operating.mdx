Every lesson so far has described *what* AWS offers. This one is about *how you actually talk to
it* — which sounds like plumbing, and is in fact an entire exam task statement, because the
choice between clicking and describing is the difference between an estate you can reason about
and one you cannot.

Underneath, there is only one AWS: **every route ends at the same API.** The console is a
website that calls it, the CLI is a program that calls it, CloudFormation is a file that calls
it. Nothing can be done in one that cannot be done in another.

## Infrastructure as code, and why it matters more than it sounds

**AWS CloudFormation** takes a template — YAML or JSON — describing the resources you want, and
creates them as a **stack**. Change the template and it works out the difference; delete the
stack and it removes everything it created.

The properties that make this a different way of working:

- **Repeatable.** The same template builds identical development, test and production
  environments. "It works in test" stops being a coincidence.
- **Reviewable.** Infrastructure changes arrive as a diff someone can read before they happen.
- **Reversible.** A failed stack update rolls back automatically.
- **Free.** You pay only for the resources it creates.

Related names worth recognising:

- **AWS CDK** — write the infrastructure in TypeScript, Python or Java and have it *generate*
  CloudFormation. For teams who would rather use a programming language than YAML.
- **AWS SAM** — a slimmer template dialect specifically for serverless applications.
- **AWS Elastic Beanstalk** — you hand it application code, it provisions and manages the EC2
  instances, load balancer, Auto Scaling group and monitoring for you. **Platform as a Service**,
  and it is itself built on CloudFormation. Free; you pay for the resources underneath.

<Callout type="exam">
The pairing to keep straight: <strong>CloudFormation provisions infrastructure from a
template</strong>. <strong>Elastic Beanstalk deploys an application</strong> and creates the
infrastructure for you as a side effect. If a question says "the developer wants to upload code
and not think about infrastructure", it is Beanstalk. If it says "provision a repeatable
environment", it is CloudFormation.
</Callout>

## Operating what you deployed

Deployment is the easy half. Four services cover running it, and the exam separates them
cleanly:

| Service | Answers |
| --- | --- |
| **Amazon CloudWatch** | "Is it healthy?" Metrics, logs, alarms, dashboards |
| **AWS CloudTrail** | "Who changed it?" The API audit trail |
| **AWS Systems Manager** | "Do the thing, on all of them." Patching, run commands, session access, parameters |
| **AWS Trusted Advisor** | "What should we fix?" Best-practice checks across five categories |

**CloudWatch** is the one worth a little more detail, because it appears constantly:

- **Metrics** — numbers over time. CPU, request count, queue depth. Basic monitoring is every
  5 minutes; **detailed monitoring** is every 1 minute and costs extra.
- **Alarms** — thresholds that trigger an action: notify an SNS topic, scale an Auto Scaling
  group, stop or reboot an instance.
- **Logs** — application and system logs, searchable, with retention you set. Note that getting
  OS-level metrics such as **memory usage** requires installing the **CloudWatch agent** — memory
  is not visible to the hypervisor.
- **EventBridge** — reacts to *events* (a state change, a schedule) rather than thresholds.

**AWS Systems Manager** is a bundle rather than one thing, and three parts get named:

- **Patch Manager** — patch a whole fleet on a schedule.
- **Session Manager** — a shell on an instance **without SSH, without a bastion host, and without
  opening port 22**, fully logged. A recurring right answer.
- **Parameter Store** — free configuration and secret storage.

<Callout type="gotcha">
CloudWatch does <strong>not</strong> report memory or disk usage from inside an EC2 instance by
default — the hypervisor cannot see them. A question about monitoring memory is asking you to
install the <strong>CloudWatch agent</strong>.
</Callout>

## Where AWS runs when it is not a Region

Three names for AWS outside the usual Regions, tested by their one-line purpose:

- **AWS Outposts** — actual AWS racks installed **in your own data centre**, running the same
  APIs. For workloads that must stay on-premises for latency or data residency.
- **AWS Local Zones** — a small AWS footprint in a metropolitan area, for single-digit
  millisecond latency to a nearby city.
- **AWS Wavelength** — AWS infrastructure inside **5G mobile networks**, for ultra-low latency to
  mobile devices.

The point is not that CloudFormation is clever — it is that <strong>an environment that exists
only as a series of past clicks cannot be reasoned about</strong>. That is the Operational
Excellence pillar in one story.
</Scenario>
